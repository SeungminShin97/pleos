## 제품의 출발점

사용자는 차량용 앱 공모전에 **차에서 자거나 쉬는 사람을 돕는 앱**을 제안했습니다. 이름은 **자비스 (자.peace)**입니다. 스마트폰 기능의 단순 이식보다 차량의 좌석·공조·조명과 상태를 활용하는 경험이 핵심입니다.

대표 상황은 장거리 운전 중 졸음쉼터에 주차한 뒤 잠깐 자는 경우입니다. 이후 점심시간에 방해받지 않고 자차에서 쉬는 직장인도 대상으로 추가했습니다. 첫 화면은 '졸음 감지'가 아니라 이미 쉬기로 한 사용자가 휴식을 준비하는 흐름을 지원합니다. 졸음 감지·건강 진단은 요구된 기능이 아닙니다.

사용자가 처음에 자신에게 편한 자세와 환경을 직접 맞추고 저장합니다. 앱이 적절한 수면 자세를 임의로 산출하는 제품으로 바꾸지 않습니다. 쉬고 싶은 순간에 저장한 환경을 빠르게 준비하는 것이 목표입니다.

### 시동 종료와 휴식의 관계

시동을 끄면 적용한 공조·음악·차량 앱이 유지된다는 전제를 두지 않습니다. '자리 준비 후 사용자가 전원을 끄고 쉰다'는 흐름과 '전원을 유지한 상태에서 공조·음악을 쓴다'는 흐름의 조건을 구분합니다. 차량 전원 종료 시 차량 알람이 계속 울린다고 표시하지 않습니다.

휴대폰 연동의 목적은 자동차를 원격 제어하는 것이 아니라 **차량 전원이 꺼져도 휴대폰에서 깨우기 알람을 울릴 수 있게 하는 것**입니다. 차량에서 예약 전송만 한 상태와 휴대폰 OS에 실제 예약된 상태를 구분해야 합니다.

## 현재 채택한 구현 방향과 제안의 구분

아래는 대화를 바탕으로 작성한 **현재 설계 선택**입니다. 모두 사용자가 세부 사양을 직접 지정하거나 개별 승인한 내용으로 표현하지 않습니다.

| 설계 선택 | 이유·범위 |
| --- | --- |
| P AND 정상적인 속도 0, 미확인 상태는 차단 | 운전 중 실행 금지 요구를 코드의 조건으로 구체화한 선택 |
| 변경 전 스냅샷 저장, 적용·복귀 기록 | 부분 실패·프로세스 종료 뒤 실제 상태를 확인하고 복구하기 위한 설계 |
| 사용자 요청·확인 후 이전 설정 복귀 | 알람·기어 변화만으로 좌석이 자동 이동하지 않도록 한 설계 |
| 앱 내 음성 버튼부터, Gleo 진입은 별도 검증 | 상시 호출어 실험이 핵심 프리셋 개발을 막지 않게 하기 위한 순서 |
| 좌석 위치·중단을 검증하지 못하면 수동 안내 | 자동 좌석 이동 지원이 확인되지 않은 환경의 대안. 핵심 목표가 검증됐다는 뜻은 아님 |
| Kotlin·Compose, 단일 app 모듈, demo/vehicle 변형 | 실제 초기 코드에 반영된 기술 구성 |
| Room·DataStore와 작업 기록 | 저장소 계층의 설계 제안. 의존성·DB·마이그레이션은 아직 구현하지 않음 |
| Android 휴대폰 앱 + 인증된 HTTPS 중계 | 후속 연동의 제안안. 서버·페어링·플랫폼은 아직 구현·검증되지 않았고 사용자 필수 사양도 아님 |
| VIN·원음·이동 이력을 기본 수집하지 않음 | 핵심 기능에 필요 없는 데이터 수집을 줄이는 설계 |
| 외부 음악 앱보다 사용 권한이 확보된 로컬 음원부터 검토 | 외부 앱 연동·오디오 정책 확인 전의 초기 구현 제안 |

Gleo·휴대폰·개인 호출어·차박·음악을 새로 구현할 때는 이 구분을 유지합니다. 특히 상시 호출어와 서버 연동이 첫 MVP의 필수 의존성으로 바뀌지 않도록 합니다.

## 아직 정하지 않은 제품 세부 사항

프리셋 개수와 편집 UI, 여러 좌석의 동시 적용 여부, 기본 휴식 시간, 카운트다운을 시작할 시점, 다시 울림 간격, 최종 시각 디자인, 지원할 차종·좌석의 최소 범위는 아직 사용자 확정 사양이 아닙니다. '점심 휴식', '졸음쉼터', '20분' 등 문서의 예시는 고정된 요구가 아닙니다.

좌석 위치 재현·중단·권한·기기별 지원은 기술 검증으로 구체화해야 합니다. 경미한 UI 선택은 기존 목적과 구현 범위에 맞춰 결정하고 기록할 수 있습니다. 검증되지 않은 기능을 지원한다고 가정하거나 B를 다시 현재 범위로 넣지는 않습니다.
