# 개발 인수인계와 다음 작업

현재 길찾기 범위는 Pleos 기본 내비의 목적지 변경과 경유지 추가입니다. 외부 내비와 주변 숙소 검색은 보류합니다. 앱 화면과 Gleo의 장소 검색은 졸음쉼터와 휴게소를 대상으로 합니다.

현대차 시트 메모리 슬롯 동기화는 개발 범위에서 제외했습니다. 자비스의 좌석 위치 저장과 휴식 설정 적용 및 복귀는 계속 개발합니다.

Pleos와 Android 15 휴대폰 에뮬레이터를 가상 블루투스로 페어링했습니다. Pleos의 검색 허용 후 휴대폰에서 먼저 연결을 요청하고 양쪽에서 동일한 코드를 확인했습니다. 차량 자비스에서 보낸 시각을 휴대폰 자비스에서 받은 뒤 Google 시계의 알람 목록에 활성 상태로 등록했고, 테스트 알람만 삭제했습니다. 실제 헤드유닛과 다른 제조사 시계 앱은 검증 대기입니다.

W08 차량→휴대폰 알람 요청을 추가했습니다. 두 자비스 앱에서 기존 페어링 기기를 선택하고, 휴대폰에서 수신 대기를 시작한 뒤 차량에서 주차 상태로 알람 시각을 보냅니다. 보안 RFCOMM 연결에서 수신을 확인하고, 휴대폰 사용자가 받은 시각을 확인하면 Android의 표준 알람 요청을 시계 앱으로 전달합니다. 실제 차량과 휴대폰 간 블루투스 전송 및 제조사 시계 앱에서의 등록은 실기기 검증 대기입니다.

2026-11-14 W08 검증. Android 15 휴대폰 에뮬레이터에서 자비스의 20분 요청으로 Google 시계의 타이머가 시작됐고, 시계 앱에서 취소해 타이머 입력 화면으로 돌아오는 것을 확인했습니다. 차량에서 휴대폰으로 보내는 경로는 실기기 검증 대기입니다. 현재 Pleos 에뮬레이터의 블루투스 동글 지원 범위는 [공식 설정 가이드](https://document.pleos.ai/en/docs/connect/guide/getting-started/application-development/configure-pleos-connect-emulator)를 참고합니다.

W08 휴대폰 경로에 같은 기기의 Android 시계 앱으로 타이머 시간을 넘기는 기능을 추가했습니다. 시계 앱이 지원하는 휴대폰에서만 버튼을 표시하며, 시작 여부와 취소는 시계 앱에서 확인합니다. 차량에서 다른 기기로 전송하는 기능과 Gleo 등록은 검증 대기입니다. [Android 타이머 API](https://developer.android.com/reference/android/provider/AlarmClock#ACTION_SET_TIMER), [Pleos Gleo 스키마 제출 안내](https://document.pleos.ai/docs/pleos-only/app-integration-guide/guide/deliver-schema)

W07 기본 화면에 한국어 음성 명령 연결과 화면이 열린 동안 작동하는 휴식 타이머를 추가했습니다. 음성 적용과 확인 후 복귀는 버튼과 같은 ViewModel 작업을 호출합니다. 현재 Pleos 이미지에서 음성 인식 앱과 TTS 엔진을 찾지 못했습니다. 타이머는 차량 전원과 앱 화면이 유지되는 조건을 전제로 하며, OS 백그라운드 예약이나 재부팅 복원은 제공하지 않습니다.

W06 데모 화면을 기본 입력란, 버튼과 결과 표로 연결했습니다. Pleos 에뮬레이터에서 프리셋 저장, 주행 중 적용 차단, P 정지 후 적용, 복귀 확인과 결과 표시를 검증했습니다. 화면 스타일링은 후속 작업입니다.

W05 데모 유스케이스를 추가했습니다. 저장된 설정 적용과 사용자 확인 후 복귀를 직렬화하고, 항목별 현재 값과 P·정지를 확인합니다. 수동 변경과 결과 불명은 복구 상태로 남깁니다. 화면 연결은 W06이며, 차량 변형의 좌석 자동 제어는 W03 검증이 완료될 때까지 비활성입니다.

W04 로컬 구현과 검증을 마쳤습니다. Room 기반 관측 설정 저장, 원본 및 작업 계획의 트랜잭션, 단일 활성 세션과 재시작 복구 기반을 추가했습니다. [STORAGE_VALIDATION](STORAGE_VALIDATION.md)을 확인합니다. W03의 좌석 이동과 재현 미검증 상태는 유지하며 W05 제어 활성화와 구분합니다.

W03 검증 결과: 좌석 11개 축의 capability와 30개 위치값 조회, 방향 및 STOP 콜백을 확인했습니다. 현재 이미지에서 실제 위치 변화가 없어 이동 효과, 중단 효과와 임의 위치 재현은 미검증이며 W03 전체 완료 조건은 충족하지 않았습니다. 증거와 다음 조건은 [SDK_VALIDATION](SDK_VALIDATION.md)을 확인합니다. 자동 좌석 적용은 보류합니다.

2026-11-08 로컬 업데이트: W01 실행 환경과 첫 화면을 검증하고 W02 AAOS 읽기 전용 adapter를 추가했습니다. 아래 초기 코드 지도는 기존 커밋 기준이며, 변경 파일, 검증 결과와 한계는 [LOCAL_VALIDATION](LOCAL_VALIDATION.md)을 확인합니다. 다음 단계는 W03이며 차량 쓰기 제어는 아직 없습니다. 현재 변경은 로컬 작업 상태로, 기존 CI 커밋의 검증 결과와 구분합니다.

## 작업 순서와 완료 조건

자비스가 이미 열린 상태에서 Gleo가 다음 검색을 전달하도록 차량 Activity를 `singleTop`으로 지정했습니다. Pleos 에뮬레이터에서 태인 검색을 열어 둔 뒤 합성 음성으로 영동선 강릉 방면 검색을 요청했고, 같은 화면의 검색어가 바뀌며 15곳이 표시됐습니다.

Pleos Gleo에서 “자비스에서 영동선 강릉 방면 쉴 곳을 검색해 줘”를 합성 음성으로 시험했습니다. 앱을 강제 종료한 뒤 Gleo가 `OPEN_REST_PLACES`에 `영동선 강릉 방면`을 전달했고 앱에 15곳이 표시됐습니다. 방향 검색 단위 테스트에서는 강릉이 기점인 반대 방향 쉼터가 제외되는 것을 확인했습니다.

숙소 검색을 스키마에서 제외한 빌드로 재검증했습니다. Pleos Gleo가 자비스 기능 3개를 등록했고, 앱을 강제 종료한 뒤 같은 검색 Intent를 직접 보내자 `영동선 강릉 방면`과 결과 15곳이 표시됐습니다. 별도 시험에서도 앱을 강제 종료한 뒤 같은 요청을 합성 음성으로 입력했습니다. Gleo가 발화를 인식하고 `OPEN_REST_PLACES`에 `영동선 강릉 방면`을 전달했으며 자비스의 검색 결과 15곳을 확인했습니다.

공공데이터포털의 전국 목록에서 졸음쉼터 253곳과 휴게소 215곳을 받아 앱에 포함했습니다. 이름, 노선과 방향으로 검색하며 시설 정보와 분류 필터를 표시합니다. Pleos에서 화면의 갱신 버튼으로 468곳을 받아 저장했습니다. 네트워크를 끈 뒤 앱을 다시 실행했을 때도 468곳이 표시됐고, 갱신 실패 후 저장 파일의 체크섬이 유지됐습니다. 저장본이 없거나 7일 이상 지난 경우 검색 화면에서 자동으로 갱신합니다. Pleos에서 저장 시각을 오래된 값으로 바꾼 뒤 검색 화면을 열어 새 저장본과 468곳 표시를 확인했습니다. 현재 경로에 따른 정렬은 후속 구현입니다. [졸음쉼터 표준데이터](https://www.data.go.kr/data/15028203/standard.do), [휴게소 표준데이터](https://www.data.go.kr/data/15025446/standard.do)

Pleos 기본 내비에서 태인 졸음쉼터를 목적지로 설정한 뒤 횡성(인천)휴게소를 경유지로 추가했습니다. 최종 안내 정보에 태인 목적지와 횡성(인천) 경유지가 함께 있었고, 자비스 화면에도 경유지 추가 확인이 표시됐습니다.

기존 경로가 변경될 수 있음을 목적지 설정 확인창에 표시합니다. Pleos에서 횡성(강릉)휴게소를 선택해 확인한 뒤, 내비 안내의 목적지가 횡성(강릉)으로 바뀌고 자비스에 목적지 설정 확인이 표시된 것을 검증했습니다.

지정 시각 휴대폰 알람을 Pleos와 Android 15 에뮬레이터에서 검증했습니다. Pleos의 UTC−08:00 기준 08:28을 블루투스로 보냈고, UTC 기준 휴대폰은 같은 시점을 16:28로 표시했습니다. 휴대폰 자비스에서 확인 후 Google 시계에 16:28 알람이 등록된 것을 확인했으며 해당 시험 알람을 삭제했습니다. 휴대폰에서의 실제 울림과 차량 및 휴대폰 양쪽 동시 예약은 별도 검증 항목입니다.

Pleos에서 1분 차량 알람을 예약한 뒤 `KEYCODE_SLEEP`으로 화면을 끄고 시험했습니다. 예약 직후 Android 전원 상태는 `Dozing`이었으며, 알람 알림은 `Asleep` 상태에서 게시됐습니다. 시험 후 화면을 다시 켰습니다. 음향 출력과 차량 전원 종료는 이 시험에서 확인하지 않았습니다.

지정 시각 차량 알람은 Pleos에서 P와 속도 0 상태로 화면에서 예약했습니다. AlarmManager에 `RestAlarmReceiver`가 등록됐고, 에뮬레이터 시각 03:46에 `vehicle_rest_alarm` 채널의 알람 알림 게시를 확인했습니다. 별도 예약을 화면에서 취소한 뒤 AlarmManager의 활성 목록에서 제거됐고, 제거 이력에 `alarm_cancelled`가 기록됐습니다. 음향 출력, 화면 꺼짐과 절전 상태는 별도 검증 항목입니다.

Pleos Connect 2.1.0의 D 및 10 km/h 상태에서 `passenger-drive` 검증을 실행했습니다. 조수석과 뒷좌석 좌우의 이동 및 STOP 요청이 차량 서비스에 도달했으나 모두 `50001` 오류를 반환했습니다. 현재 이미지에서는 주행 중 전후 조정에 성공하지 못했습니다. 시험 후 P 복귀를 확인했습니다.

후속 개발에는 전국 졸음쉼터와 휴게소 데이터 연동, Pleos 기본 내비의 목적지 변경과 경유지 추가, TMAP과 카카오내비 확장, 음성 장소 검색과 숙소 검색, 전기차 휴식과 차박, 휴식 음악, 앱 자체 호출어 실험과 화면 디자인을 포함합니다.

동승석 전후 조정을 추가했습니다. 데모 D 상태에서 조수석과 뒷좌석 좌우의 위치가 각각 바뀌는 것을 확인했습니다. 차량용 조정 화면은 Pleos 디버그 에뮬레이터에서 동작하며 운전석을 대상에 포함하지 않습니다. 이동 전후 위치를 다시 읽어 명령 응답과 위치 변화를 구분합니다. Virtual Console로 D와 10 km/h를 설정해 차량용 화면에서 해당 상태와 버튼 활성화를 확인했습니다. 터치 시험에서는 결과 문구가 바뀌지 않아 주행 중 SDK 호출과 위치 변화는 확인되지 않았습니다. 시험 후 P 복귀를 확인했습니다.

| W04 | 프리셋·세션·작업 기록 영속화 | 지원하는 항목만 저장, 변경 전 스냅샷을 쓰기 전에 커밋, 재시작 시 복구 자료 유지 |
| W05 | 적용·복귀 유스케이스 | 직렬 실행·중복 차단·실행 조건 재확인·읽기 확인·부분 실패·수동 변경 충돌·복구 흐름 검증 |
| W06 | P0 화면 연결 | 최초 자세 저장 → 주행 시 차단 → P·정지 후 적용 → 결과 표시 → 확인 후 복귀 시연 |
| W07 | 앱 내 STT/TTS·차량 알람 | 터치와 같은 유스케이스 호출, 예약·오디오·전원 한계 확인. 차량 전원 유지 조건 표시 |
| W08 | Gleo·휴대폰 알람 확장 | 실제 등록·호출 또는 휴대폰 OS 예약 확인·취소까지 검증한 경로만 지원 표시 |
| 후속 | B·개인 호출어·차박·외부 음악 | 핵심 흐름 이후 별도 착수. B는 현재 보류 유지 |

W01~W03은 기능 가능 범위를 결정하기 위한 작업입니다. 좌석 자동 재현이 확인되기 전에 전체 UI를 완성했다고 처리하거나 임의의 SDK setter를 만들어 연결하지 않습니다. 개발 도중 구현 선택을 바꾸면 이유와 영향을 DESIGN에 기록합니다.

기술 미확정 사항은 '실패'와 '미시도'도 구분합니다. 접근 권한이나 환경이 없으면 미검증이라고 남기고 UI에서 해당 지원을 보장하지 않습니다. 검증 가능한 다른 부분은 계속 개발합니다.

## 적용·복귀 구현 시 유지할 설계

- 활성 세션을 한 개로 직렬화하고 중복 요청이 원래 스냅샷을 덮어쓰지 않게 합니다.
- 실제 쓰기 전에 선택한 항목의 현재 값과 실행 계획을 영속 저장합니다.
- 작업 상태는 PLANNED·DISPATCHED·CONFIRMED·FAILED·UNKNOWN을 구분합니다.
- 타임아웃·프로세스 종료 후 자동 재실행·반대 방향 이동 대신 실제 상태를 다시 확인합니다.
- 복귀는 앱이 바꾼 항목을 중심으로 처리하고 사용자가 수동 변경한 항목은 충돌 선택을 제공합니다.
- 기어 변화·알람·도착 이벤트로 좌석을 자동 복귀시키지 않습니다.
- 단위·범위·여러 축의 이동 순서를 차종 공통 상수로 추정하지 않습니다.
- 전체 상태 전이·화면·데이터·수용 테스트는 [DESIGN](DESIGN.md)의 3·4·8·9·10절을 따릅니다.

## 알람·음성 단계에서 유지할 조건

차량 알람은 OS 예약 API와 실제 오디오 출력을 검증합니다. 차량 전원 종료 후 지속을 보장하지 않습니다. 휴대폰에는 예약·변경·취소의 ID·revision과 실제 OS 예약 확인 응답이 필요하며, 중계 수신·푸시 도착만으로 완료 표시하지 않습니다.

앱 내 STT는 유한한 인식 세션부터 구현합니다. Gleo 진입은 상시 앱 마이크 점유와 구분합니다. 개인 호출어·사용자 녹음은 별도 인식 기술·권한·수명주기 검증 과제입니다. 음성 명령도 차량 상태 검사와 사용자 확인을 통과해야 합니다.

## 작업 완료 후 남길 것

변경한 기능·지원 범위, 실제 통과한 시나리오, 실패·미검증 항목, 빌드·SDK·이미지 버전과 다음 작업을 docs에 반영합니다. 코드 변경에 맞는 빌드·도메인 테스트·통합 검증을 수행하되 문서 변경만으로 실제 차량 테스트를 했다고 기록하지 않습니다.

첫 P0 데모는 '직접 저장 → 주행 상태 차단 → P·정지 적용 → 항목별 결과 → 사용자 확인 복귀'입니다. 공모전 제출·시연 범위와 근거는 [REFERENCES](REFERENCES.md)와 DESIGN 11절을 확인합니다.
